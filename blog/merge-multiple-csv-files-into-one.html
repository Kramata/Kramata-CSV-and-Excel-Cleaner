How to Merge Multiple CSV Files Into One

Three methods compared — Windows CMD, Excel Power Query, and a repeatable no-code way.

Twelve monthly exports. One CSV per store, per region, per client. Each file has the same columns and you need them stacked into a single file you can actually work with. There are three common ways to do this on Windows — each with genuine uses and genuine catches.

Two kinds of "merge" — know which you need

Stacking (append): same columns, more rows — twelve months into one year. That's what this guide covers.

Joining (by a key): pulling columns from a second file by matching an ID — the VLOOKUP job. That's a different operation; see merge CSV files by a common column or merge two spreadsheets without VLOOKUP.

Method 1 — Windows CMD: copy *.csv combined.csv

Open Command Prompt, navigate to the folder containing your files, and run: 

copy *.csv combined.csv

That's it. Windows concatenates every .csv file in the folder into one file. It takes seconds regardless of how many files you have.

The catches most guides bury:
  • Every header row repeats. File 2's header lands as a data row in the middle of your output. You get twelve header rows scattered through the combined file.
  • Columns must already match exactly. One file with "first_name" and another with "First Name" stack into misaligned columns — silently, with no error.
  • No cleanup, no dedupe. Whatever inconsistencies are in the source files are stacked directly into the output.
  • Order depends on filename alphabetical sort. Not always what you want.

Best for: a quick one-off when your files are already clean, already have identical headers, and you're going to clean the result manually anyway.

Method 2 — Excel Power Query: Combine Files

Power Query is the right tool for this inside Excel. Open a blank workbook and go to Data › Get Data › From File › From Folder. Select your folder, and Power Query will show you all the files it finds. Click Combine & Transform to merge them into one table.

  1. Data › Get Data › From File › From Folder.
  2. Select the folder containing your CSVs.
  3. Click Combine & Load (for a quick merge) or Combine & Transform (to apply cleaning steps first).
  4. Power Query adds a "Source.Name" column so you know which file each row came from.
  5. Load the result into a sheet or directly to a table.

Power Query handles mismatched headers better than CMD, and it saves the query so you can refresh it when new files arrive. It's genuinely the right answer if you're already living in Excel.

Where Power Query hits its wall:
  • Excel's row limit is ~1,048,576. If your combined files exceed that, Power Query can't load the result.
  • It lives inside a workbook. The merged table lands in Excel — you can't get thirty clean files back out without scripting.
  • The Query Editor has a learning curve. The friendly buttons cover the basics; anything custom leaks into M code fast.
  • Sharing is awkward. A colleague needs the same workbook and a path that resolves the same way on their machine.

Best for: analysts who work in Excel and need a refreshable merged table inside a workbook. For depth on the Power Query approach, see Power Query vs the alternatives.

Method 3 — The repeatable way: clean first, then combine

The problem CMD and Power Query share is that they stack first and leave cleaning for later — or skip it entirely. The files drift: one export has "First Name", another "first_name", a third has an extra space. Stack them raw and the inconsistency is baked in.

The cleaner approach runs cleanup on each file before combining:

  1. Put all the files in one folder.
  2. Build a cleaning recipe on a single sample file — normalize headers, fix dates, dedupe, whatever they all need.
  3. Run that recipe across the folder in batch mode.
  4. Choose merge into one file as the output.
  5. The result is one file where every row passed through the same cleanup before being combined.
Next month: drop the new files into the folder and run the same recipe. Identical logic, identical output structure — no rebuilding from scratch, no repeated header rows.

What about files too large for Excel?

CMD has no row limit — it concatenates raw text regardless of size. But the result is uncleaned and the header-row problem gets worse with large files. Power Query caps at Excel's ~1M row ceiling, which many combined datasets exceed.

FAQ

What is the quickest way to merge CSV files on Windows? The CMD command copy *.csv combined.csv combines all CSV files in a folder into one in seconds. The catch: every file's header row repeats in the output and there is no cleanup. Works for a quick one-off when files are already clean and columns are identical.

Can Excel Power Query merge multiple CSV files? Yes — Get Data › From Folder does exactly this. The limitations: you're capped at ~1 million rows (Excel's row limit), the result lands inside a workbook (you can't get separate cleaned files back out), and the Query Editor has a learning curve.

Do the files need identical columns? For CMD, yes — mismatched columns stack silently into the wrong places. For Power Query and Kramata, mismatched headers are surfaced and can be resolved before combining.

What if the files are too large to open in Excel? Excel caps at ~1,048,576 rows. CMD has no limit but produces a raw result. Kramata processes through DuckDB with no row-count ceiling — large files combine without the memory pressure that crashes Excel.

Can I mix CSV and Excel files? CMD only handles CSV (it concatenates raw text). Power Query and Kramata both read CSV and Excel and can combine them.

Is it reproducible next month? CMD is not — you re-run it manually each time with no saved cleanup. Power Query saves the query inside the workbook but sharing it is awkward. Kramata saves a portable recipe file you re-run in one click or share with anyone.
